## Легенда приоритетов

- **A** — критически важные шаги. Без них проект не работает и не демонстрируется вообще (сквозной happy path).
- **B** — основные шаги. Обязательные пункты именно этого задания (12. Станция техобслуживания) и требования к "доказуемости" edge-cases.
- **C** — дополнительные шаги — внедрение собственной фичи (роботизация станции + ИИ-диагностика).
- **D** — полировка, исправления некритичного функционала.

Внутри грейда цифра = порядок выполнения. Если время заканчивается — сначала жертвуем D, потом C, потом непроверенными частями B. Грейд A не режем.

## C1 — зафиксированный скоуп кастомной фичи

- **Робот** — программная симуляция на посту: очередь задач, состояния `свободен / выполняет / ошибка / готово`, длительность выполнения = длительность услуги из каталога, небольшой случайный шанс сбоя.
- **ИИ-модуль** — по профилю автомобиля и услуге генерирует рекомендацию доп. работ. Pluggable: реальный LLM при наличии ключа, иначе rule-based генератор с тем же интерфейсом.
- Робот и ИИ автоматизируют то, что по базовому Заданию 12 делает "мастер" — согласование доп. работы клиентом остаётся обязательным шагом.
