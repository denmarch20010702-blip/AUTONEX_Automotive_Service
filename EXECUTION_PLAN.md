## Легенда приоритетов

- **A** — критически важные шаги. Без них проект не работает и не демонстрируется вообще (сквозной happy path).
- **B** — основные шаги. Обязательные пункты именно этого задания (12. Станция техобслуживания) и требования к "доказуемости" edge-cases.
- **C** — дополнительные шаги — внедрение собственной фичи (роботизация станции + ИИ-диагностика).
- **D** — полировка, исправления некритичного функционала.

Внутри грейда цифра = порядок выполнения (A1 выполняется раньше A2 и т.д.). Если время заканчивается — сначала жертвуем D, потом C, потом непроверенными частями B. Грейд A не режем.

## C1 — зафиксированный скоуп кастомной фичи

Чтобы "роботы + ИИ" не расползлись в неопределённый объём работы, фиксирую скоуп:

- **Робот** — программная симуляция на посту: очередь задач, состояния `свободен / выполняет / ошибка / готово`, длительность выполнения = длительность услуги из каталога, небольшой случайный шанс сбоя (для честной демонстрации обработки нештатной ситуации).
- **ИИ-модуль** — по профилю автомобиля (марка/модель/пробег/история обслуживания) и выполняемой услуге генерирует рекомендацию дополнительных работ с текстовым обоснованием. Реализация — pluggable: если задан ключ реального LLM API, вызывается модель; если нет — используется собственный rule-based генератор с тем же интерфейсом (проект остаётся быстро разворачиваемым локально без секретов, как требует общее условие про эмуляцию внешних сервисов).
- Робот и ИИ не заменяют человека-мастера — они автоматизируют то, что по базовому заданию 12 делает "мастер": выполнение работ и предложение доп. работ. Согласование доп. работы клиентом остаётся обязательным шагом (тоже требование задания).
